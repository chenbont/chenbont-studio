# 官方中继服务定价方案

> 定稿于 2026-02。官方中继 = Studio Relay 的零配置托管版，与自托管开源中继永久免费并行。

## 定价结构

| 层 | 价格 | 内容 |
|---|---|---|
| **Free** | ¥0 | 1 台手机主控连接 + 1 个访客（只读 + 单次审批需主控确认），基础消息转发 |
| **Pro** | ¥10/设备/月 或 ¥100/设备/年（约 2 个月免费） | 更多设备、多访客、完整远程控制功能 |

## 设计原则

- **免费层 = 个人单人使用的最小真实场景**：1 主控 + 1 访客，长期免费而非限时试用
- **访客角色免费层只读为主**：看会话、看 diff；单次操作需主控确认——免费版天然安全，凸显 Pro 的多设备完整控制价值
- **不做功能阉割**：免费层只做连接数/频次限流，功能完整，避免口碑受损
- **升级路径清晰**：接第 2 台手机或第 2 个访客时，客户端内提示升级
- **年付引导**：¥100/年锁定现金流，减少月付流失

## 官方中继 vs 自托管

| | 官方中继 | 自托管（开源 Studio Relay） |
|---|---|---|
| 配置 | 扫码即用，零配置 | 自备服务器，自行部署维护 |
| 费用 | Free 层免费 / Pro ¥10/设备/月 | 服务器成本自担（VPS 约 ¥20–40/月） |
| 适用 | 个人、小团队、想省事的用户 | 私有化、内网、合规要求场景 |

## 与代码实现的对应关系（2026-04 更新）

本方案是产品侧定价草案；代码落地的关键约定见 `service/README.md#定价` 与
`mcode/apps/desktop/src/main/relay/identity.ts`、`.../mobile/PairingManager.ts`：

- **账户与支付不在本仓库**：由独立运营服务端承载（微信/GitHub OAuth、支付、发票）。
  本仓库（`service` + `mcode`）保持 account-less —— 中继只读订阅令牌、不落地用户数据；
  桌面端持久化令牌并在配对/连接时提交。
- **授权锚定 `licenseId`，不锚定 `machineHash`**：重装系统或换电脑后，在新机器用同一邮箱
  重新登录验证码，运营端即签发同一 `licenseId` 的订阅令牌恢复 Pro，不消耗新配额。「设备」= 受控端（被远程控制的
  手机），非桌面端装机数。
- **访客模型**：本仓库已实现中继侧 `guest` 角色（反滥用语义，凭证不分配通道），与本文
  “免费层含 1 访客”一致；“只读 + 单次审批”的权限细粒度在运营端/客户端按产品节奏补齐。
- **配额维度**：中继在 `Store.Allocate` 内**原子**执行配额闸门——Pro 按 `licenseId` 在全部
  桌面间计数（`maxChannels`，返回 `403 quota_exceeded`）；Free 无令牌时按设备
  `machineHash` 计 1 个并发通道（超额同样 `403 quota_exceeded`）。配对受控手机数由桌面端
  按令牌 `maxControllers` 本地卡。
- **原型**：`prototypes/` 暂未含定价卡片；如需可视化，可加一张 Free/Pro 对比卡 + 设置内
  订阅卡片（邮箱登录状态、升级入口跳运营站）。
